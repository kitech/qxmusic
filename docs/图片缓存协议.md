# 图片（封面/图标）缓存协议（qlmusic + qskmusic 共用）

## 1. 目录（两端一致，桌面共享）

- 桌面：`$XDG_CACHE_HOME/qxmusic/covers`（缺省 `~/.cache/qxmusic/covers`）
- Android：`<CacheLocation>/qxmusic/covers`
- 测试覆盖：环境变量 `QXIMAGE_CACHE_DIR`（完整路径，优先生效）
- **扁平结构**：不按专辑/歌单/歌手/分类分子目录

## 2. 文件命名（不算哈希）

- 取封面 URL 最后一段原始文件名：`.../109951163265698885.jpg?param=96y96`
  → `109951163265698885.jpg`
- 过滤 `/ \ : * ? " < > |` 与控制字符；总长上限约 120 字节（保留扩展名）
- URL 无扩展名 → 追加 `.img`（解码靠内容魔数，不依赖扩展名）
- 同名文件已存在 → **保留旧文件不覆盖**

## 3. 存储内容

- 只缓存**原图**（剥离 `?param=`），显示时本地按目标尺寸缩放
- 生成型图标（identicon / 歌手首字母 / 分类色块）**只进内存**，不落盘

## 4. 写入

- 写 `<name>.part` → `rename(<name>.part, <name>)` 原子替换
- 两个进程同时写同一 URL：先完成者生效，后者看到已存在直接复用

## 5. 容量与清理

- 上限：桌面 400MB、移动 200MB（单目录）
- 触发时机：启动后异步 trim + **每 50 次网络成功落盘触发一次**（长会话不再无限增长）
- 按 mtime LRU 淘汰；跳过 1 小时内新文件与 `.part`
- `.part` 残渣：超 1 小时的在 trim 时清除（崩溃/杀进程遗留）

## 6. 内存缓存

- `QPixmap` LRU，key = `URL:px`；上限桌面 16MB、移动 12MB（qsk 启动时按 `Q_OS_ANDROID` 设置）
- 命中顺序：内存 → 磁盘 → 网络 → 兜底图标

## 7. 网络与失败

- 请求头带 `Referer: https://music.163.com`
- **UA（全仓统一）**：图片下载与 libncm API 层使用同一 UA（netease-music
  库 pc 串：macOS Chrome/Edge 124）。qsk 桌面 QNAM、Android Java
  ImageFetch、ql libcurl 三处写死同串；Go 侧由库管理天然一致。
  注意：库内个别 service（如热搜）按风控走 mobile UA，属正常
- **歌曲下载停滞防护**：qsk `setTransferTimeout(30s)`（无数据流动即中止）；
  ql `CURLOPT_LOW_SPEED_LIMIT=1 / LOW_SPEED_TIME=30`（只杀停滞，不限总时长）
  ——两版同型缺陷"连上后不传了"会永久卡死串行下载队列，已各加停滞超时
- qskmusic 桌面（Qt6 QNAM）：`transferTimeout(15s)`（卡死请求释放并发槽）
- Android：走 Java `ImageFetch`（HttpURLConnection，Qt 未捆绑 OpenSSL）
- qlmusic（libcurl）：失败 1 秒后重试一次，仍失败才负缓存
- 404/403 进负缓存（仅内存，5 分钟），不重复请求
- 下载失败重试一次（1 秒后），仍失败用兜底图标

## 8. 日志（双通道：qDebug + LogModel，tag=icon）

- `[ICON] hit=mem|disk|net miss url=… px=… kind=album|playlist|artist|category`
- `[ICON] evict files=N remainBytes=M`
- **降噪**：qskmusic 的 `hit=disk` / `hit=mem` 仅 qDebug，不进 LogModel（高频命中会把 Logs 页有效记录挤掉）；网络/失败类（net-fail、miss、corrupt、decode-failed、cache-write-failed）仍双通道

## 9. 高 DPI 规则

- **qskmusic**：调用方传**逻辑尺寸 dp**，`IconItem::pxForDp(dp) = clamp(round(dp × screen dpr), 1..256)`，
  loader 请求/内存 key 均用物理 px —— dpr=3 的 40dp 播放条封面 → 120px 请求，不再发虚
- **qlmusic**：桌面 dpr 视为 1×，调用方直接传目标 px；Retina 上限 256 同样适用
- 磁盘缓存 key 不含 px（原图一份）；内存 key 含 px

## 10. 歌手头像（P5）

- 数据源：libncm `ncm_artist_detail(id)`（ABI 3）→ `{"id","name","pic_url"}`
- qskmusic：`NcmApi::artistAsync/artistDone`（std::thread + detach）；qlmusic：`NcmService::loadArtist/artistLoaded`（工作线程任务）
- `pic_url` 走同一缓存链（§1–§7）；展示：播放条歌手行前 20px 圆形
- 失败 / `pic_url` 为空 → `qximage::letterAvatar`（首字母圆头像，仅内存）
- 构建期要求 `out/include/ncm.h` 为 ABI 3（含 `ncm_artist_detail` 声明）；旧头文件机器需先重建 libncm

## 11. 损坏缓存处理

- 磁盘文件解码失败（非图片/截断）→ **删除该文件** + 5 分钟负缓存
- 日志 `corrupt-on-disk`（warn）/ `decode-failed`（error），避免永久兜底与每次重绘重复解码

## 12. 圆角（两端视觉一致）

- qskmusic：`IconItem::setCornerRadius(6–8)`，QPainter 路径绘制
- qlmusic：`IconLoader::rounded(src, px, radius)`（mask 方案，Qt3/4/6 通用）；
  曲目行 36/6、搜索行 40/6、播放条 52/8、队列 150/10、歌单详情头图 40/8

## 13. 下载时机（lazy，绘制驱动）

- qskmusic：`IconItem` 构建时只查内存/磁盘；**网络请求推迟到首帧
  `updatePaintNode`**（scene graph 只对可视 item 调用，离屏行不下载）；
  滚动到可视区才排队下载
- qlmusic：paintEvent 循环先做可视性 `continue` 再调 `cover()`（原有 lazy 语义）
- 去重：qsk inFlight/队列 key = 纯 URL（同 URL 跨 px 不重复下载）；
  ql 按 URL 去重（原有）
- 失败收敛：单次下载内部重试 1 次 + 负缓存 5 分钟 +
  **会话级失败封顶 2 轮**（ql `m_fails`）；qsk `m_retry` 每 URL 每会话 ≤1 次重试

## 14. Android 明文 HTTP 与图片插件核对

- **插件无缺口**：APK 内 `lib/arm64-v8a/libplugins_imageformats_*` 含
  qgif/qicns/qico/qjpeg/qsvg/qtga/qtiff/qwbmp/qwebp（androiddeployqt 自动打包）；
  png 由 QtGui 内置。启动日志 `[ICON] decodable formats` 可复核。
- **故障根因**：NCM CDN 封面是 `http://`；Android 9+（targetSdk ≥ 28）默认禁明文，
  `ImageFetch` 的 `HttpURLConnection` 抛异常后旧实现静默返回 null → 入负缓存 →
  整屏兜底图标（"有些能画"= 历史已落盘缓存，非新下载成功）。
- 修法：
  1. Manifest `android:usesCleartextTraffic="true"`（与桌面行为对齐）
  2. `ImageFetch.fetch` 先升级 `https://`，失败回落原地址
  3. 非 2xx / 异常打 `ImageFetch` 日志（不再静默）
  4. 负缓存 TTL 300s → 60s（恢复更快）
- 判读：修复后新封面日志 `[ICON] hit=net ... ct=image/jpeg`；
  `adb logcat -s ImageFetch` 无 `CLEARTEXT` 报错。
